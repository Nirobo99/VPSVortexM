Привет, Cascade! Продолжаем разработку мессенджера VortexyM. Мы успешно завершили Этап 0 (фундамент). Теперь переходим к Этапу 1: Пользователи и профили.

Цель этапа: реализовать все функции, связанные с пользовательским профилем, кроме стикеров и платных услуг. Это включает расширение модели пользователя, редактирование профиля, публичный/приватный режим, чёрный список, кастомизацию (темы), регистрацию с дополнительными вопросами (год животного и математический пример) с блокировкой на 24 часа, защиту от брутфорса, а также создание базовой админ-панели для просмотра пользователей.

Важно: все изменения должны быть безопасными, использовать уже настроенные механизмы (JWT, Redis, Sequelize). Код должен быть хорошо структурирован, с комментариями.

План действий (подзадачи):

1. Расширение модели User

· Добавь в модель User (файл server/models/User.js) недостающие поля (некоторые уже есть, проверь и дополни):
  · birthYear (integer, allowNull false) – уже должно быть.
  · role (enum: 'user', 'admin', defaultValue: 'user') – уже есть.
  · avatar (string, defaultValue: 'default-avatar.png') – уже есть.
  · stickerLimit (integer, defaultValue: 5) – уже есть.
  · invisible (boolean, defaultValue: false) – уже есть.
  · invisibleExpiry (date, allowNull true) – уже есть.
  · Добавь поле bio (text) – краткая информация о пользователе.
  · Добавь поле isPublic (boolean, defaultValue: true) – публичный или приватный профиль.
  · Добавь поле theme (string, defaultValue: 'light') – для кастомизации темы (light/dark/custom).
  · Добавь поле customColors (json, defaultValue: null) – для хранения пользовательских цветов (если нужна тонкая настройка).
· Выполни синхронизацию модели с БД (sequelize.sync). Можно использовать alter: true в server.js (уже должно быть).

2. Редактирование профиля (API)

· Создай новый маршрут в server/routes/users.js (или добавь в auth.js, но лучше выделить).
· Реализуй PUT /api/users/profile – обновление данных профиля (name, bio, avatar, isPublic, theme, customColors).
  · Доступно только авторизованным пользователям (проверка JWT).
  · Валидация входных данных.
  · Обновление записи в БД.
· Реализуй GET /api/users/me – получение данных текущего пользователя (для отображения профиля).
· Реализуй GET /api/users/:id – получение публичной информации о другом пользователе (если профиль публичный).
  · Если профиль приватный, возвращать только базовую информацию (имя, аватар) или ошибку доступа.

3. Публичный/приватный режим профиля

· При запросе профиля другого пользователя проверяй поле isPublic.
· Если профиль приватный и запрашивающий не является владельцем, возвращай ограниченные данные (например, только имя и аватар) или статус 403.

4. Чёрный список (BlockedUser)

· Создай модель BlockedUser в server/models/BlockedUser.js:
  · id (integer, primaryKey)
  · userId (integer, foreign key to User) – кто блокирует
  · blockedUserId (integer, foreign key to User) – кого блокируют
  · createdAt (date)
· Установи связи: User.hasMany(BlockedUser, as 'blockedUsers', foreignKey 'userId').
· Реализуй API для чёрного списка:
  · POST /api/users/block/:userId – добавить пользователя в чёрный список.
  · DELETE /api/users/block/:userId – удалить из чёрного списка.
  · GET /api/users/block/list – получить список заблокированных.
· При отправке сообщения, создании чата и т.д. (в будущих этапах) нужно будет проверять, не заблокирован ли получатель.

5. Кастомизация профиля (темы, цвета)

· На клиенте (фронтенд) нужно будет реализовать интерфейс для выбора темы и настройки цветов, но пока сосредоточимся на бэкенде.
· Убедись, что поля theme и customColors сохраняются и возвращаются в API профиля.

6. Регистрация с дополнительными вопросами и блокировка на 24 часа

· Модифицируй эндпоинт POST /api/auth/register:
  · Добавь в тело запроса поля: birthYear (уже должно быть), animalAnswer, mathAnswer.
  · На сервере создай словарь (объект) соответствия годов животным, например:
    ```javascript
    const animalMap = {
      1990: 'Лошадь',
      1991: 'Овца',
      1992: 'Обезьяна',
      1993: 'Петух',
      1994: 'Собака',
      1995: 'Свинья',
      1996: 'Крыса',
      1997: 'Бык',
      1998: 'Тигр',
      1999: 'Кролик',
      2000: 'Дракон',
      2001: 'Змея',
      // ... можно продолжить
    };
    ```
  · Проверь animalAnswer: должно совпадать с animalMap[birthYear]. Если нет – ошибка.
  · Проверь mathAnswer: правильный ответ на пример "2+2*2" = 6. Если ответ не 6 – ошибка.
  · При любой ошибке (неправильный ответ на любой вопрос):
    · Запиши в Redis ключ blocked:email:<email> с TTL 24 часа (86400 секунд).
    · Запиши в Redis ключ blocked:ip:<ip_адрес> (получи IP из req.ip или req.headers['x-forwarded-for']) тоже с TTL 24 часа.
    · Верни ошибку 400 с сообщением "Неверные ответы на контрольные вопросы. Регистрация заблокирована на 24 часа."
  · Перед началом регистрации проверяй, нет ли таких ключей в Redis. Если есть – возвращай ошибку о блокировке.
· Обнови документацию API.

7. Защита от брутфорса (ограничение попыток входа)

· Добавь middleware для rate limiting на эндпоинт /api/auth/login.
· Используй Redis для хранения счётчика попыток:
  · Ключ: login:attempts:ip:<ip>.
  · При каждой неудачной попытке увеличивай счётчик и устанавливай TTL, например, 15 минут.
  · Если счётчик превышает 5, возвращай ошибку "Слишком много попыток. Попробуйте позже."
· При успешном входе удаляй ключ.

8. Базовая админ-панель (просмотр пользователей)

· Создай отдельную группу маршрутов для админа в server/routes/admin.js.
· Добавь middleware isAdmin, который проверяет req.user.role === 'admin'.
· Реализуй GET /api/admin/users – получение списка всех пользователей (с пагинацией).
  · Доступно только админам.
  · Возвращай основные поля (id, email, name, role, birthYear, createdAt и т.д.).
· Для тестирования можно вручную установить роль admin у какого-либо пользователя через БД.
· (Опционально) Добавь простой интерфейс на фронтенде для просмотра списка пользователей (отдельная страница /admin/users), но сейчас можно ограничиться бэкендом.

9. Интеграция с фронтендом (минимально)

· На клиенте создай страницу профиля (/profile), где пользователь может просматривать и редактировать свои данные (имя, bio, аватар, настройки приватности, тему).
· Создай страницу регистрации с дополнительными полями (год рождения, животное, математический пример).
· Добавь обработку ошибок от сервера (блокировка и т.п.).
· Добавь страницу входа с обработкой rate limiting.
· Создай сервис api.js для вызовов к бэкенду с использованием axios и JWT.
